# 会议纪要（dsh-plugin-meeting-minutes）

把**一场会**变成一份**能看、能带走、能落到日历上**的会议纪要：

- **实时录音转文字**：面板里直接录音，说完一句停顿约 1.5 秒就切段识别，文字滚动追加到会议；录音在后台运行，关掉弹窗、切到其他面板都不中断。也可导入本机录音/视频文件（wav/mp3/m4a/mp4/aac），长音频自动切片。
- **本地说话人识别**：实时转写时在本机给每段标上「说话人1/说话人2…」，可以手动改名；全本地推理，音频不出本机。
- **自动入库**：腾讯会议本地录制结束后自动发现、转写、存成「待整理」会议；也可以把导出的纪要/录音丢进监控目录，自动入库，不用每次手动导入。
- **腾讯会议纪要文本**：把客户端里的「智能纪要 / 转写」复制粘贴进来，或导入 `.txt/.md/.json` 导出文件；不用给插件账号密码。
- **AI 总结**：调用当前默认模型，生成一句话结论、关键要点、会议决策、风险/待确认、分节纪要，并把行动项抽成待办。
- **可视化会议纪要文档**：面板里就是一个排版好的纪要页（封面信息、结论高亮、要点卡片、决策清单、风险提示、分节正文、待办表），还能一键导出**独立 HTML**（可直接打开/打印/分享）或 Markdown。
- **待办写入任务日历**：勾选确认后的待办，写入「任务日历」插件（已安装时），按截止/开始时间提醒；再次生成纪要不会重复写入已确认的待办。

## 一、面板怎么用

左侧栏「会议纪要」图标 → 打开面板。左边是会议列表，右边是选中会议的纪要文档。

| 场景 | 操作 |
| :-- | :-- |
| 现场开会、手机/电脑录音 | 顶部「录音」→ 标题留空也行 → 「开始实时转写」→ 边说边出字；可点「后台录音」关掉弹窗继续用软件，底部录音条随时停止 |
| 已有录音文件 | 顶部「导入」→ 选音频/视频文件 → 自动转写并建会议 |
| 腾讯会议纪要 | 顶部「导入」→ 粘贴文本（或选 `.txt/.md/.json`）→ 建会议 |
| 生成/重生成纪要 | 右上「AI 生成纪要」，几十秒后右侧文档更新 |
| 变成任务 | 在待办表里勾选 → 「写入任务日历（N）」；已写入的显示日历任务 id |
| 带走文档 | 「导出 HTML」或「导出 Markdown」；文件写到 `~/.dsh/meeting-minutes/exports/` |
| 改纪要文字 | 直接编辑待办的负责人/截止/优先级/备注后写入；标题、日期、参会人可在会议头部编辑 |

### 自动入库（腾讯会议结束后自动留存）

- **腾讯会议本地录制**：插件只读腾讯会议 macOS 客户端的 `local_record_data` 表，发现「录制完成 + 文件还在本机」的记录后，自动用本机 SenseVoice 转写并建会议（标题用腾讯会议的录制标题，找不到就用「录音纪要 时间」），标记为自动入库、等你有空整理。
- **监控目录**：在「自动入库」设置里添加任意目录（一行一个），新出现的 `m4a/mp4/wav/mp3/aac/webm/mov` 会自动转写；`txt/md/docx` 会直接抽文本入库；腾讯会议导出的纪要文件放进去即可。
- 扫描每 30 秒一次，默认开启、可随时关闭；同一来源不会重复导入，失败最多重试 3 次；面板会提示「已自动导入：xxx（待整理）」。
- **限制**：腾讯会议「云端智能纪要」没有个人版 API，插件只能拿到本机录制或你导出的文件；如果只用云录制/云转写，需要在腾讯会议里导出，或使用企业版开放平台凭证接 API。

### 标题：先默认，后修改，AI 自动命名

- 录音/新建会议都可以**不填标题**：自动用「录音纪要 2026-10-21 17:30」这类占位名，先开始再说，不用在会议开始时停下来想名字。
- 会后随时可以改：会议文档右上「编辑会议信息」里改标题、日期、参会人。
- 让 AI 生成纪要时，如果标题还是自动占位名，模型会顺便起一个真正的会议名（例如「Q4目标预算与上线排期」）并自动替换；**你自己写过的标题不会被改**。接口里传 `autoTitle: false` 可以关闭自动改名。
- 这样「会议很急」和「纪要整理拖到最后」不再冲突：先录/先导入，命名和整理都交给后续 AI 步骤。

### 实时转写与后台录音

- 录音使用 Web Audio 采集 16kHz 单声道 PCM，按**停顿切段**（默认静音 1.5 秒即切）编码成 WAV 发给本机 SenseVoice，识别结果滚动追加到会议。首段文字通常在开口后 **3–5 秒**出现。
- 录音状态、音频节点与发送队列都在页面模块作用域，**关闭录音弹窗、切换到对话或其他面板、最小化参数面板都不会停止录音**；底部常驻「录音中」浮动条显示计时、已转写字数、最近一句，并提供「停止」「打开纪要」。
- 停止时会先发完最后一段再收尾，自动刷新会议与列表；期间可以继续操作软件（只有关闭/刷新整个页面会中断）。
- 本机识别服务只提供整段识别，所以这里是「按停顿切段滚动识别」而不是逐字流式；切段边界偶尔会把一句话切成两段（识别文本仍完整保留）。如果需要真正逐字上屏，可以后续接云厂商流式 ASR。
- **录音时长没有产品上限**：面板录音和 agent/命令行录音都会一直录到你主动停止。命令行脚本的 `--seconds` 只是测试/演示用的「到点自动停」参数，不传即不限时。
- 浮条可以直接**拖动**（拖到不挡视线的地方），位置会记住；双击浮条回到默认底部居中。agent 录音的浮条带「停止录音」按钮——点它只是向录音端发停止请求，录音端会发完最后几段再合并，通常几秒到十几秒。
- 停止后，页面会先显示约 3 秒的「录音已结束 · 已保存 N 秒 · 打开纪要」提示，再收起提示条并刷新列表；这样停录不会被误认为断线。整场录音会合并成**一份**音频副本，记录里保存相对路径 + 整场 sha256 + 时长。

### 实时转写：停顿 1.5 秒即切

- 实时转写按**停顿**切段，而不是固定时长：一段话说完、静音达到阈值，就立刻把这段送去识别，所以「说完一句、停一下」就能看到文字，不用等满一个固定窗口。
- 默认阈值 **1.5 秒**（最灵敏的一档，说完一两秒就出字）；想更稳重可改成 3 / 5 秒，在浏览器控制台调整后刷新页面：

  ```js
  // 3 = 更稳重（适合连续长句、手边有环境噪声）；5 = 最稳重（几乎只在明显长停顿时切）
  localStorage.setItem('dsh.meeting.vad.silenceSeconds', '3') // 支持 1.5 / 3 / 5
  localStorage.removeItem('dsh.meeting.vad.silenceSeconds')      // 恢复默认 1.5 秒
  ```

- 阈值只影响「什么时候切段」，不影响识别模型本身；识别仍是本机 SenseVoice 整段识别，切段边界偶尔切断一句话时文本也不会丢。
- 一直连续说话不会让一段无限变长：除了「静音到阈值」，还会在约 **10 秒**时强制切一段，避免单片过长。
- 录音采的是 16kHz 单声道 PCM16，切出来的每段编码成 WAV 再上传，浏览器端完成，不依赖 ffmpeg。

### 本地说话人识别

- **全本地推理**：实时录音转写时，每一段语音切片都在本机跑 3D-Speaker **CAM++** 中文说话人向量模型，把同一个人的连续发言聚成「说话人1 / 说话人2 / …」；音频和声纹特征都不出本机，不调用任何云服务。
- 只对**实时录音的切片**做说话人标注（每段有独立边界才谈得上「谁说的」）；导入的音频/文本是整段文件，没有发言人边界，转写照常但不加说话人前缀。
- **模型**：`3dspeaker_speech_campplus_sv_zh-cn_16k-common.onnx`，**约 28MB**（sha256 `f682b514c05d947ee3fa91cd6ec6c5c7543479a128373fa29b1faedccd21fd11`），默认放在 `$DSH_HOME/meeting-minutes/speaker/`；首次使用会自动下载并校验 sha256。
- **native 库来源**：在 Slark 里优先复用 runtime 自带、已按 Slark 签名的 `sherpa-onnx-node`（macOS hardened runtime 的库校验会拒绝其它 Team ID 签名的 `.node`），只有独立 `dsh web` 时才用插件自己安装的副本；两处都找不到就安静降级（转写照常，只是不加说话人前缀）。
- **提前备模型（可选）**：打包/部署或离线环境可以预先下好，模型已在且校验通过时脚本直接短路、不会重复下载：

  ```
  npm run prepare:speaker-model
  # 等价于：node scripts/prepare-speaker-model.mjs
  # 指定别的 DSH_HOME：node scripts/prepare-speaker-model.mjs --home /path/to/dsh-home
  ```

  脚本会打印模型路径、大小、sha256 与「已存在且校验通过 / 已下载并校验通过」。
- **推理依赖**：`sherpa-onnx-node`（随插件安装，native 预编译二进制，不需要本地编译；macOS arm64 会自动装 `sherpa-onnx-darwin-arm64`）。
- **关掉说话人识别**：启动宿主前设 `MEETING_SPEAKER_DISABLE=1`，转写照常，只是不做说话人分离、不加「说话人N：」前缀。进阶：`MEETING_SPEAKER_MAX` 限制最多认几个人（默认 8），`MEETING_SPEAKER_THRESHOLD` 调聚类阈值（默认 0.58，越高越不容易把两个人并成一个）。
- **转写行格式**：带说话人标签的转写每行是 `说话人N：文本`；识别出的说话人列表存在会议记录的 `speakers: [{ id, label }]` 里，面板上可以改名，改名只改标签、不重新推理（转写里的旧标签会同步替换）。

### 腾讯会议的纪要文本从哪来

腾讯会议个人版没有公开的「读取我的纪要」接口，本插件走**文本/录音导入**，三条路都行：

1. **会后**：腾讯会议客户端 →「历史会议 / 会议详情」→ 智能纪要或转写记录 → 全选复制 → 粘贴到「导入」。
2. **会中录制**：开启了云录制/本地录制时，会后可下载录音或转写文本；音频文件直接拖进「导入」即可转写。
3. **本地录制文件**：macOS 上通常在 `~/Documents/TencentMeeting/` 下（按版本可能不同），选 `.m4a/.mp4` 导入即可。

> 如果你有企业版开放平台凭证、希望插件直接拉取纪要，需要在插件里接腾讯会议 OpenAPI；当前版本刻意不内置账号体系，避免把密钥写进配置。

### 语音识别说明

- 默认使用 Harness 内置的**本机 SenseVoice**（`@deepseek-ai/dsh-experimental-voice-input-bundle` 提供），音频不离开本机。
- **第一次转写**会下载识别模型（本机实测约 242MB，面板顶部会显示「准备中/下载进度」）；网络受限时下载可能失败，此时面板会提示改用文本导入。
- 识别要求 16kHz 单声道 PCM16 WAV；面板在浏览器里完成解码/重采样/切片（≤90 秒一片），不依赖 ffmpeg。
- 从本机文件转写（Agent 工具）时，非 canonical 音频会用 macOS 自带 `afconvert` 转码。

## 配套 AI Skill

插件启用后会自动向 Harness 注册技能 `meeting-minutes-workflow`：AI 在会议纪要、录音转写、待办确认、加日历任务等场景会主动加载它，按「存原文 → 总结 → 展示待办 → 用户确认 → 写入日历」的流程执行，并遵守“不确认不写日历”等护栏。

- 技能随插件生命周期注册/注销，不需要单独安装。
- 在会话技能目录里看到 `meeting-minutes-workflow` 即表示生效。
- 只装任务日历插件时没有这个技能（它属于会议纪要插件）。

## 三、安装 / 卸载

推荐直接安装会议套件（一次装两个插件）：

```
@zhangguitao666/meeting-suite
```

只装会议纪要：

```
dsh-plugin-meeting-minutes@1.4.0
```

在 Harness 的 **Plugins → Add plugin** 里填上面的包名，或在 Agent 里让 `plugin_manager install_bundle` 安装；装好后刷新页面（⌘R）。

装好后**刷新一次网页**（新浏览器端 bundle 只在页面重新加载时进入启动清单），左侧栏出现「会议纪要」图标。

- 停用但保留：`plugin_manager set_bundle dsh-plugin-meeting-minutes enabled=false`
- 彻底卸载：`plugin_manager remove_bundle dsh-plugin-meeting-minutes`
- 套件伞包：`plugin_manager remove_bundle @zhangguitao666/meeting-suite`
- 依赖：宿主自带的 `tools`、`webServer` 服务；`speechToText`（语音识别）与 `llm`（总结）为可选服务，缺失时对应按钮会给出中文提示。

## 四、数据与接口

- 会议数据：`$DSH_HOME/storages/meeting-minutes.json`（原子落盘；损坏时备份为 `.corrupt-<时间戳>` 并以空库启动）。自动入库的开关、监控目录与已导入来源也记录在这里。
- 导出文件：`$DSH_HOME/meeting-minutes/exports/`。
- 说话人模型：`$DSH_HOME/meeting-minutes/speaker/`（CAM++ 约 28MB；`npm run prepare:speaker-model` 可预下载，`MEETING_SPEAKER_DISABLE=1` 关闭说话人识别）。
- 宿主 HTTP：`/dsh-meeting/*`（仅回环地址），完整契约见 `CONTRACT.md`；浏览器面板通过它读写，不依赖生成式 Remote 通道。
- 写入日历走任务日历插件的公开接口 `/dsh-task-calendar/tasks`，两个插件可独立安装/卸载；未安装任务日历时会明确提示。

## 六、已知限制

- 腾讯会议没有个人版开放接口：能自动拿到的是**本机录制**（或你导出到监控目录的文件）；云端智能纪要需导出或企业 API。
- 本机 SenseVoice 模型首次使用需联网下载；下载失败时只能走文本导入（或改用其它机器）。
- 实时转写按停顿切段（默认静音 **1.5 秒**即切），切段边界可能切断一句话（文本不丢）；真正逐字流式需要云 ASR，暂未接入。阈值可用 `localStorage['dsh.meeting.vad.silenceSeconds']` 调成 1.5/3/5。
- 说话人识别是本机离线聚类：人数与「谁说的」不保证 100% 准确（音色相近可能被并成一个人、同一人偶尔被拆开），识别结果可以在面板里手动改名。
- 录音时长上限取决于模型与内存，超长会议建议分段导入；单次总结会把超长文本压到 14 万字以内（保留头尾）。
- 「写入任务日历」只是创建任务，不会反向删除日历里已建的任务；改时间请在任务日历面板里改。
